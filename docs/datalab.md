# 한국관광 데이터랩 활용

어떤 탭을 왜 쓰는지, 그리고 쓰면서 알게 된 제약을 남긴다.

## 받는 방법

데이터랩은 **무단 수집을 금지한다.** 크롤링하지 않고, 사람이 사이트에서 내려받은
CSV를 `data/datalab_raw/` 에 그대로 둔다.

다운로드 폴더는 탭별로 쪼개져서 내려온다. 한 지역에 폴더가 여러 개 생기는데,
`scan_downloads()` 가 폴더명의 지역명으로 합치므로 폴더명을 바꾸지 않는다.

```
data/datalab_raw/
├── 20260925200010_제주특별자치도_2023-2025_데이터랩_다운로드/   관광소비 탭
└── 20260925200050_제주특별자치도_2023-2025_데이터랩_다운로드/   관광지 탭
```

## 쓰고 있는 탭

| 탭 | 파일명 끝 | 쓰는 곳 |
|---|---|---|
| 관광소비 (내국인) | `관광소비_내국인.csv` | 미식·쇼핑 테마 비중 |
| 인기관광지 (전체) | `인기관광지_전체.csv` | 역사·자연 테마 비중, 앱 매칭 검증 |
| 성·연령별 소비 분포 | `성연령별 내국인 관광소비 분포.csv` | 타깃 프로파일 |
| AI 관광분석 — 연관지역 | `연관지역.csv` | 지역 간 동선 간선 후보 |

## 받아뒀지만 아직 안 쓰는 탭

| 탭 | 왜 안 쓰나 |
|---|---|
| 평균 체류시간 추이 | `pipeline/staytime.py` 에서 쓸 예정 |
| 방문자 체류특성 | 위와 같음 |
| 외국인 관심 관광지 (5개 언어) | 앱의 다국어 기능과 연결할 여지가 있다 |
| 주요 유료관광지점 입장객 수 | 인기관광지와 겹쳐서 보류 |
| 지역 맛집 | 앱의 `food` 카테고리와 대조해볼 만하다 |

## 알아둘 것

### 인기관광지는 '관광지 목록'이 아니라 '방문지 목록'이다

통신·카드 데이터 기반이라 공항·호텔·백화점·골프장이 상위권에 들어온다.
부산은 TOP8 중 5곳이 백화점·아울렛이고, 제주·서울도 1위가 공항이다.

그래서 테마 비중이나 매칭률을 계산할 때 모수를 걸러야 한다
(`verify.py` 의 `NOT_TOURISM`·`OUT_OF_SCOPE`).

### 분류 체계가 TourAPI와 같다

인기관광지의 `분류` 컬럼 값이 한국관광공사 TourAPI 분류체계와 같은 체계다.

```
데이터랩 CSV : 자연경관(하천/해양) · 역사유적지 · 도시공원 · 전시시설 · 랜드마크관광
TourAPI      : NA02 자연경관(하천‧해양) · HS01 · VE03 도시공원 · VE07 전시시설 · VE01
```

구분자만 다르다(`/` vs `‧`). 즉 **앱 장소를 TourAPI로 재분류하면 데이터랩과
같은 축 위에 놓인다.** 이게 `pipeline/tourapi.py` 의 근거다.

TourAPI 대분류 10종: `NA 자연` `HS 역사` `VE 문화` `EX 체험` `LS 레저`
`FD 음식` `SH 쇼핑` `AC 숙박` `EV 축제` `C01 추천코스`

참고로 최신 API(`KorService2`)는 `cat1/cat2/cat3` 이 빈 값이고
`lclsSystm1/2/3` 으로 옮겨갔다. 옛 문서를 보고 `cat1` 을 읽으면 빈 문자열만 나온다.

### 지역 표기가 앱과 다르다

데이터랩은 `경상북도 경주시`, 앱은 `경주`. 광역시는 자치구까지 쪼개 주는데
(`부산광역시 해운대구`) 앱은 한 덩어리로 쓴다.

`data/mapping/regions.csv` 가 변환표다. `match=prefix` 는 첫 어절만 맞아도
적용하고(광역시), `match=exact` 는 전체가 같을 때만 적용한다. `경상북도` 를
prefix로 두면 `경상북도 경주시` 가 `경북` 이 되어버려서 구분이 필요하다.

### 체류시간은 지역 단위 총량이다

`평균 체류시간` 은 **1회 방문의 총 체류시간(분)** 이다. 경주 1,237분(20.6시간),
전국 기초지자체 평균 1,048분. 앱의 `stayMin`(장소당 40~90분)과 단위가 달라
직접 비교할 수 없다.

지역 단위로 "앱이 짜주는 일정 총량이 현실적인가"를 검증하는 데만 쓴다.
